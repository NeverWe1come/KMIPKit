### Coverage boundaries

- `verified` means caller-facing behavior is exercised by protocol and fake-transport tests; it does not claim a complete OASIS profile or official Test Case pass.
- `scoped_verified` means the KMIPKit client contract is exercised, while full behavior depends on caller sequencing, server state/policy, or use of material outside this client library. This release adds no hidden timers, per-object call history, cryptographic-use enforcement, or automatic follow-up operations.
- The approved Check clarification is implemented: a failed Check response may carry and expose `Usage Limits Count`, `Cryptographic Usage Mask`, and `Lease Time` without a success `Unique Identifier`; protocol, fake-client, compiled C consumer, Java, and Python regressions exercise these fields and the complete ordered generic response TTLV. The typed accessor withholds an identifier included in a failed response, while the generic TTLV copy remains available.
- The pinned source does not link operation-specific official Test Case IDs to these 48 client ledger requirements. Table-derived tests are not formal conformance evidence.
