## Cross-cutting result

1. The 52 existing typed response readers remain available through `ClientResponseView`; the four asynchronous flows expose operation-specific response views in Rust, C, Java, and Python. C returns a fixed-width v1 record with borrowed spans; Java and Python wrappers retain the outcome owner and reject access after it is closed.
2. Every successful typed batch result exposes its complete decoded Response Payload tree through `ClientBatchItemResponse::raw()`. Missing payloads remain absent; failure and Pending behavior follows the response tree actually received.
3. The Response Header is directly available through `ClientBatchItemResponse::response_header_raw()`. Protocol-level `ResponseHeaderView` and `ResponseBatchItemView` also expose ordered raw nodes.
4. C, Java, and Python return owned copies for generic payload/header access and have explicit release/close behavior. Async response wrappers preserve owner lifetime; correlation is accessed through temporary callbacks/spans without copying into wrapper state. The test matrix exercises vendor tags nested in Key Block and Server Information across Rust, C, Java, and Python.
5. `Item::as_structure()` makes every nested Structure reachable without parsing its parent into a lossy typed model. Values remain accessible as ordered `Item`s, including repeated and unknown tags.
6. The raw API exposes the decoded TTLV tree. The decoder discards padding, so it does not promise exact wire-byte reproduction.

## Explicit exclusions and source notes

- Set Endpoint Role (§6.1.54, Table 332) is client-initiated but deferred to 1.1 under the approved product scope. It is not part of these 56 rows.
- Table 286 is preserved under its exact pinned caption and table content discrepancy; the response stays generic until the approved `KMIPKIT-DISC-039` resolution governs semantic interpretation.
- Poll uses asynchronous result semantics. A terminal Poll response may carry the original operation's Response Payload; a Pending Poll response has no payload and carries correlation data under §8.6 Table 399.
- Query Asynchronous Requests keeps its Response Payload generic under the approved discrepancy handling for Table 286; no field-level typed payload is exposed.
