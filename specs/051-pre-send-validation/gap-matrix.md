# KMIPKIT-0051 Operation Validation Gap Matrix

This matrix accounts for every operation supported by the `ClientOperation`
enum at the KMIPKIT-0050 base (`b2c455a99a54c1a93876aa2e1dbbaa78f509b3d6`).
OASIS sources refer to the pinned KMIP v2.1 document. The payload table is the
normative schema source; the module column identifies the current typed model
and serializer to audit. Every row must receive an explicit result in the
implementation column before this feature is complete.

The existing client performs common Batch Item/message checks and selected
operation-local checks. It does not yet expose one borrowed, structured
validator covering all operation payloads. Serializer field order is already
operation-specific; this work must not replace it with numeric tag sorting.
The independent field audit confirmed that the Get Constraints Request Payload
(Table 229) and Ping Request Payload (Table 271) are empty; the other 54
in-scope Request Payload tables contain fields.

### Additional operation prose to audit

- Certify and Re-certify: Certificate Request Type is required when Certificate Request Value is supplied.
- Encrypt, Decrypt, Hash, MAC, MAC Verify, Sign, and Signature Verify: Data, digested data, MAC/signature data, correlation, initialization, finalization, IV/nonce, and authenticated-encryption fields have operation- and multipart-specific conditions. Use each operation's prose; do not reuse one universal multipart rule.
- Revoke: Compromise Occurrence Date SHOULD be supplied for key-compromise and CA-compromise reasons and SHALL NOT be supplied for other Revocation Reason values.
- Query Asynchronous Requests: Operations and correlation-value filters have matching semantics described in its operation prose.
- Register: Object type, object representation, and attributes have conditional rules beyond the compact field list.
- Table-level requirements and descriptive prose must be checked against the exact source during T002; this inventory is a review aid and not executable schema data.


## T002 field-level rule audit

The following per-use inventory was extracted from the pinned OASIS KMIP 2.1
HTML `specification/oasis/kmip-2.1/upstream/kmip-spec-v2.1-os.html`. Each field
row records the Request Payload table in the operation overview above, its
one-based table order, the §11.56 Table 487 tag when the tag name is exact, and
the table's REQUIRED cell verbatim. `Pending` is intentionally used while the
type-definition, nested-schema, local-condition, and model-evidence portions
of T002 are being audited; it does not mean the protocol requirement is
optional. The operation descriptions reproduced here are the exact field-row
descriptions used to evaluate conditions. Rule IDs are assigned in ascending
§6.1 operation and payload field order; they will not be reused.

The source contains 56 supported Request Payload tables and 189 field uses.
Get Constraints (§6.1.22, Table 229) and Ping (§6.1.36, Table 271) have empty
payload tables and therefore no operation-field rule IDs. The client-initiated
Set Endpoint Role (§6.1.54, Table 331) remains explicitly excluded as deferred
to 1.1; §6.2 server-initiated operations remain out of scope.

#### Source ambiguity notes

- `Any Object (Section 2)` is the Request Payload table's polymorphic object
  description, not an exact §11.56 Table 487 tag name. Its tag/type must be
  resolved against the selected §2 object structure and written as a
  source-backed union or `Pending`; do not substitute the `Object Type` tag.
- `Asynchronous Correlation Values` is the plural container in Table 285. The
  singular Asynchronous Correlation Value tag is 0x420006, but it is not
  silently assigned to the plural container. Its own container tag/type is
  `Pending` until an exact normative encoding is found.

## Existing implementation and borrowed-validation audit

The current typed request models keep their top-level fields private, and their
serializers construct top-level payload fields using the operation's defined
order and TTLV type. That is a useful invariant, but it does not validate raw
nested `Structure`/`Item` values, semantic ranges, or conditional relationships.
T003 must cite the exact model and serializer for any rule considered safe by
construction.

| Existing path | Baseline behavior | KMIPKIT-0051 work |
|---|---|---|
| `crates/kmipkit-client/src/execute.rs::ClientRequest::validate_local_shape` | Borrowed preflight currently covers multipart checks for Encrypt, Decrypt, Hash, MAC, MAC Verify, Sign, Signature Verify, plus Register. | Expand to one public borrowed validation report for all 56 variants; retain batch ID checks and run before message build/transport. |
| `crates/kmipkit-client/src/execute.rs::Client::execute` | Existing preflight precedes message construction and `transport.exchange`; local failures map to `NotSent`. | Use the same report as public validation and test zero exchanges/writes. |
