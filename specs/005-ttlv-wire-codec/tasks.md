# Tasks: KMIP TTLV Wire Codec

**Input**: Design documents in `/specs/005-ttlv-wire-codec/`.

**Prerequisites**: `spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/rust-ttlv-codec.md`, and `quickstart.md`.

**Implementation gate**: Before T001, verify the feature specification is approved under repository governance, the branch is updated from the active `release/1.0.0` head, the merged 004 Tag/Item APIs and Accepted ADR-0010 are inspected, and `docs/adr/0011-reserved-tag-decoding-policy.md` has been reviewed/accepted. Before any work relies on FR-013, a human must also (1) accept `docs/adr/0012-caller-requested-wire-encoding-policy.md`, (2) approve this feature specification, and (3) explicitly approve the proposed enforceable boundary: public generic values and bounded decoding remain in `kmipkit-ttlv`; a future private `kmipkit-client` writer requires an `OperationEncodingPermit` owned by the module that will contain `Client::execute`; execute will accept only a closed set of concrete typed KMIP requests, never a caller-supplied `Item`, raw body, or caller-implementable conversion trait. These three approvals approve a design only. KMIPKIT-0005 does not create `Client::execute`, define the caller-facing API, define or mint the permit, or add a production writer callsite. T003's encoder remains private and uncalled by production code; its unit tests are the only callsites in this feature. The first client feature/spec owns the API, permit type/private constructor, execute-only mint and writer callsite, parent-restricted writer visibility, exact-one callsite/mint audit, and request-path integration test. The candidate first-client feature PR must contain both the sole production callsite and its owner-through-transport integration test. CI must run and pass that test against the candidate callsite before merge, enablement, or release; until then, the release branch must contain no production callsite or secret-bearing send. The first client integration test must prove closed typed inputs, owner lifetime through partial writes until transport success/error return, drop/zeroization, `AGENTS.md` §8 failed-request delivery-state reporting, and no automatic retry. If review rejects the boundary or it cannot be enforced, do not approve or implement a secret-bearing request path. If an approval gate is unmet, do not start tasks relying on FR-013; update this gate evidence and stop. The separate 1.0 traceability gate for `KMIPKIT-REQ-SPEC-10.1.2-001` remains open until every applicable client 1.0 Structure has approved typed-spec ownership, implementation, and executable order-verification references; it does not block generic codec implementation.

**Organization**: Strict Red, Green, Refactor commits with DCO sign-off. Each phase's Red commit records failing tests before production code changes.

**Independent test**: Private `kmipkit-client` wire-encoder unit tests compare all eleven type families and nested Structure encodings byte for byte. These do not claim the client request-path/transport integration test owned by the first client feature/spec.

**Requirements**: `KMIPKIT-0005-FR-001`–`FR-003`, `FR-012`–`FR-013`; `KMIPKIT-0005-NR-001`–`NR-005`; `KMIPKIT-0005-SC-001`.

## Phase 3: User Story 2 — Decode a complete generic TTLV item (Priority: P1)

**Goal**: Decode valid supported TTLV without losing modeled values or Structure ordering, and reject malformed inputs without a partial public Item.

**Independent test**: `cargo test -p kmipkit-ttlv --test codec_negative` exercises malformed byte cases and decoder preservation; `cargo test -p kmipkit-client` exercises the private encoder's canonical round-trip unit tests.

**Requirements**: `KMIPKIT-0005-FR-004`–`FR-006`, `FR-010`; `KMIPKIT-0005-NR-001`–`NR-006`; `KMIPKIT-0005-SC-002`–`SC-003`.

- [ ] T005 [US2] Add test-only module wiring under `#[cfg(test)]` in `crates/kmipkit-ttlv/src/lib.rs` and a test-only `decode_candidate` stub/seam in `crates/kmipkit-ttlv/src/codec_red_tests.rs`. Keep the seam and any supporting test types private to that cfg(test) module; Red cases call this seam directly, not the not-yet-existing production `decode` function or public `codec` facade. Give the stub deliberately incomplete behavior so the tests compile and fail on behavior assertions, never on unresolved imports or missing production symbols. Cover valid OASIS vectors and negative cases for truncated headers/values, all fixed widths, empty Big Integer, invalid UTF-8/Boolean, unsupported Type, nested boundaries, trailing bytes, assigned/extension Tags, the resolved Reserved-tag behavior, and padding extents. Do not add external integration tests against APIs not implemented yet (Red commit).
- [ ] T006 [US2] Promote the T005 test-only seam to the production one-item checked decoder, public `codec` facade, type-specific lengths, value decoding, ordered Structure construction, and resolved Tag disposition in `crates/kmipkit-ttlv/src/codec/decoder.rs` and `codec/mod.rs` (Green commit). Preserve/adapt T005's behavioral unit cases so they exercise the production decoder, then add or retain external integration tests in `crates/kmipkit-ttlv/tests/codec_api.rs` proving callers can import and use the public `decode` API; move public malformed-input coverage into `tests/codec_negative.rs` only after these symbols exist.
- [ ] T007 [US2] Refactor offset/boundary handling and errors into focused helpers; verify no input or payload is retained/formatted and no unsafe code is added in `crates/kmipkit-ttlv/src/codec/decoder.rs` and `crates/kmipkit-ttlv/src/codec/mod.rs` (Refactor commit).
- [ ] T008 [US2] Add bounded, deterministic generated round-trip property tests in the private client encoder unit tests at `crates/kmipkit-client/src/wire_encoder.rs`: encode codec-acceptable generic values through the private writer, decode through the public `kmipkit-ttlv` decoder, and compare with a canonicalized expected model plus child order. Exclude empty Big Integers, minimally sign-extend unaligned Big Integer octets to a multiple of eight for the expected model, preserve aligned octets exactly, and keep dedicated vectors for that normalization. Use a fixed seed and no new property-testing dependency.
