# Public API manifest maintenance

The reviewed source of truth for the complete 1.0 cross-language API is
`specification/api/public-api.json`, validated by
`specification/api/public-api.schema.json`. It uses manifest v2 and retains the
KMIPKIT-0012 registry declarations as a registry slice while owning the full
public-package, declaration, operation-readiness, and parity inventory. The
first six generated destinations preserve the registry slice; the five
additional destinations carry the full public API contract. Only declarations
and capabilities marked `declared` or `verified` may appear in generated API
outputs. Blocked inventory records are review metadata and do not create API
signatures. Do not edit generated output by hand.

The generator uses only the Python standard library at runtime. Its tests use
the pinned dependencies in `tools/api_manifest/requirements-test.txt`. Run the
commands in an activated virtual environment so they do not change the global
Python installation:

```text
python -m venv .venv
```

Activate it with `.venv\\Scripts\\Activate.ps1` in PowerShell or
`source .venv/bin/activate` in Bash/zsh, then install the pinned test
dependency as shown below.

## Regenerate after an approved manifest change

From the repository root, run:

```text
python tools/api_manifest/generate.py --write
python -m pip install -r tools/api_manifest/requirements-test.txt
python -m unittest discover -s tools/api_manifest/tests -v
python tools/api_manifest/generate.py --check
git diff --check
```

The `--write` command validates the manifest and schema before atomically
writing the eleven fixed destinations. Version 2 also checks the 56-operation
`client_1_0` inventory against the checked-in normative catalog, leaving Set
Endpoint Role (§6.1.54) deferred to 1.1, and resolves all approval,
declaration, and parity references offline. Review the source manifest change
and all generated diffs together in the same PR. Update the handwritten
adapters and their tests to match the manifest; generated signatures do not
implement runtime behavior.

## Verify without changing files

For local checks and CI, use:

```text
python tools/api_manifest/generate.py --check
python -m unittest discover -s tools/api_manifest/tests -v
```

`--check` compares the checked-in generated bytes with fresh output and exits
with an error if any output is missing or stale. It does not create or modify
files. CI must use this mode so an uncommitted regeneration cannot hide a stale
generated artifact.

## Review boundaries

- Change the manifest only for an approved public API contract change; keep its
  stable requirement IDs and language mappings aligned with the feature spec.
- Change the schema or generator only when the manifest format or rendering
  contract needs an explicit update, with focused tests in
  `tools/api_manifest/tests/`.
- Never add output paths supplied by the manifest. The generator owns a fixed,
  validated destination set.
- Include the manifest, generator/schema changes, generated files, adapter
  implementations, parity tests, and traceability updates in one feature PR.
